# Matter Lab — фиксированный релиз

Это снимок приложения с собственной версией, контрольными суммами и Docker image. Текущие исходники разработчика не используются и не монтируются. Веб-сайт и API работают в Linux-контейнере; физические расчёты используют Rapier/WASM. Финальный 3D-рендер выполняет отдельный Mac worker через SceneKit/Metal.

## Запуск на компьютере

1. Распакуйте весь архив в обычную папку на Apple Silicon Mac с **macOS 26 или новее**. Эта сборка проверяется на macOS 26.4.1; включённый FFmpeg требует минимум 26.0.
2. Установите и запустите Docker Desktop, если его ещё нет.
3. Откройте **Start Matter Lab.command**. Сайт откроется по адресу **http://127.0.0.1:4315**. Первый запуск загружает включённый Docker image локально, без внешнего registry.
4. Для остановки откройте **Stop Matter Lab.command**. Данные сохранятся.

Node, FFmpeg, его библиотеки и готовый Metal renderer включены в релиз. На компьютере получателя не нужны Homebrew, npm, Swift или исходники проекта. Приложение не устанавливает глобальные пакеты. Docker Desktop распространяется отдельно.

Если macOS блокирует полученный архив, используйте штатное «Открыть» / настройки разрешения запуска для доверенного скачанного приложения. Сборка имеет только ad-hoc подписи отдельных runtime binary: Developer ID и notarization в этом релизе отсутствуют.

## Данные и проверка

Авторские проекты, экспортированные видео, кэш и журналы создаются в папке **data** рядом с launcher. Это общая writable volume контейнера и worker; файлы не записываются в исходники или Docker image. Перед обновлением сохраните data и укажите её новому релизу. **Verify Matter Lab.command** сверяет неизменяемые файлы с SHA256SUMS; пользовательские данные в проверку не входят.

Для другого каталога или портов:

```sh
MATTER_LAB_RELEASE_DATA_DIR="/path/to/my-data" \
MATTER_LAB_WEB_PORT=4315 MATTER_LAB_WORKER_PORT=4316 \
./worker/runtime/bin/node ./packaging/launcher.mjs start
```

Команды launcher: `start`, `stop`, `status`, `verify`. `start --no-open` запускает сайт без открытия браузера. Состояние и закрытый одноразовый токен находятся в data/run с доступом только владельцу. Worker принимает авторизованные HTTP-задания от контейнера через host.docker.internal. Наружу опубликован только сайт на loopback 127.0.0.1; это локальный релиз без облака, аккаунтов и публичной публикации.

## Границы текущей поставки

- Linux-контейнер **не содержит SceneKit/Metal** и самостоятельно не производит финальный native render. Для полного экспорта Mac worker должен работать.
- Сохранённый Docker image — Linux arm64; Mac runtime — macOS arm64. Windows, Intel Mac и Linux GPU-worker в эту сборку не входят.
- Интерфейс можно развивать для телефона, подключающегося к этому серверу. Публичный доступ, HTTPS, учётные записи, мобильный touch UX и нативное телефонное приложение в текущий локальный релиз не входят. Текущий launcher специально не открывает локальную сеть.
- Музыка и контактные эффекты создаются локально. Включённый FFmpeg собран Homebrew с GPL-компонентами; тексты лицензий, рецепты и сведения о зависимости находятся в worker/runtime/licenses. Внешняя публикация бинарного дистрибутива требует соблюдения соответствующих лицензий и предоставления необходимых исходников.

## Сборка разработчиком

В репозитории: `npm run package:release`. Нужны Apple Silicon macOS, Swift CLI, Docker Desktop, установленный Node и FFmpeg. Скрипт создаёт отдельный снимок, собирает веб-интерфейс в нём, компилирует renderer, переносит runtime с полным замыканием dylib, собирает и сохраняет фиксированный Docker image, создаёт manifest / SHA256SUMS / zip. Dev-кэш и ранее созданные видео в релиз не включаются.

Для проверки полного пути контейнер → Mac worker → MP4 используется `node packaging/verify-release.mjs /absolute/path/to/release`. Проверка создаёт отдельные временные данные и не трогает обычные проекты или другие контейнеры.
